# 📄 Requirement Document

**Project:** React + TypeScript Starter Boilerplate (Testing-Ready)  
**Author:** Shourov  
**Version:** 2.0  
**Date:** November 2025

---

## 1. 🎯 Objective

To deliver a **React + TypeScript starter project** with **strict linting/formatting**, **pre-commit validation**, and **comprehensive testing support** across all layers (unit, integration, E2E, performance, accessibility, contract). The project must be **production-grade**, enforce **best practices**, and provide **developer confidence** through automated checks.

---

## 2. 🛠️ Tech Stack

- **Frontend Framework:** React (latest stable)
- **Language:** TypeScript (strict mode)
- **Bundler/Dev Server:** Vite (preferred)
- **Package Manager:** yarn (preferred)
- **Linting & Formatting:** ESLint + Prettier
- **Git Hooks:** Husky + lint-staged
- **Testing Frameworks:**
  - **Unit & Integration:** Jest + React Testing Library
  - **E2E:** Playwright (preferred) or Cypress
  - **Accessibility:** axe-core + jest-axe
  - **Snapshot Testing:** Jest built-in snapshot system
  - **Contract/API Testing:** Pact (consumer-driven contracts)
  - **Performance Testing:** Lighthouse CI + Playwright traces
- **CI/CD:** GitHub Actions

---

## 3. 📐 Code Quality & Standards

- Strict TypeScript config (`strict: true`, `noImplicitAny`, `strictNullChecks`)
- ESLint + Prettier enforced via `eslint-config-prettier`
- Accessibility linting (`eslint-plugin-jsx-a11y`)
- Import sorting (`eslint-plugin-import`)
- Commit messages follow **Conventional Commits**

---

## 4. 🔒 Pre-Commit Hook (P-Comet Hook)

- **Tooling:** Husky + lint-staged
- **Hook:** `pre-commit`
- **Validation Steps:**
  1. Run ESLint (`eslint --ext .ts,.tsx src/`)
  2. Run TypeScript type-check (`tsc --noEmit`)
  3. Run build validation (`vite build --dry-run`)
  4. Run Prettier check (`prettier --check .`)
  5. Run unit tests (`jest --bail --passWithNoTests`)
  6. Stage only passing files

---

## 5. 🧪 Testing Configuration

### Unit Testing

- **Framework:** Jest
- **Library:** React Testing Library
- **Coverage:** Minimum 80% enforced in CI

### Integration Testing

- Test React components with mocked APIs using MSW (Mock Service Worker)
- Validate component interaction and state management

### End-to-End (E2E) Testing

- **Framework:** Playwright (preferred for speed & cross-browser)
- **Scope:** User flows, routing, authentication, payment flows
- **CI Integration:** Run headless in GitHub Actions

### Accessibility Testing

- **Tools:** jest-axe + axe-core
- **Scope:** Validate WCAG compliance for all UI components

### Snapshot Testing

- **Framework:** Jest snapshots
- **Scope:** UI regression detection

### Contract/API Testing

- **Framework:** Pact
- **Scope:** Consumer-driven contract validation against backend APIs

### Performance Testing

- **Tools:** Lighthouse CI + Playwright traces
- **Scope:** Validate performance budgets (TTFB, LCP, CLS, etc.)

## 7. ✅ Best Practices

- **Code Consistency:** All commits must pass lint, type-check, build, and tests.
- **Testing Pyramid:**
  - 70% unit tests
  - 20% integration tests
  - 10% E2E tests
- **Accessibility:** All UI components must pass a11y checks.
- **Performance Budgets:** Lighthouse CI thresholds enforced in CI.
- **Contract Validation:** Pact tests run in CI to ensure API compatibility.
- **CI/CD:** GitHub Actions pipeline runs lint, type-check, unit, integration, E2E, accessibility, contract, and performance tests.
